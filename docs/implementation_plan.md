# MalthusJAX Paper: Implementation Plan

The living paper plan in [MalthusJAX](https://github.com/LeonardoDiCaterina/MalthusJAX/blob/main/docs/publication_design/living_paper_plan.md) and the sibling paper checkout's `drafts/paper-study-v2/CHANGES_PLAN.md` own the claims and decisions. This document specifies implementation and acceptance. Existing `paper-study-v2` ledgers are historical evidence. Use a fresh campaign root for new data. Paths in this plan are relative to the framework checkout unless stated otherwise.

The requested tensor-network showcase is a new composition relative to the recorded NSGA-II/NEAT island study. Preserve that study and gate the new showcase on an explicit decision about whether it supplements or replaces the current Part 3 in the paper. Part 1 likewise preserves the established two-leg comparison while adding the requested direct originals to the harness. Any change to claim scope goes through the planning notes.

## Part 1 — EvoSAX and QDax parity

| Library | A — direct original | B — adapter | C — native |
|---|---|---|---|
| EvoSAX | Upstream SimpleGA init/ask/tell | MalthusJAX EvoSAX SimpleGA adapter | Standard MalthusJAX GA mimic using imported EvoSAX operators |
| QDax | Upstream MAP-Elites with the frozen emitter and archive | MalthusJAX QDax adapter | Native MAP-Elites mimic |

**A–B** uses the existing original/adapter numerical, operator, and HLO checks, plus direct original observations in the new harness. Record assertion scope and tolerance. HLO inspection supplies indirect evidence about compiled work. Repeated synchronized timing supplies the measured runtime effects. **B–C** is the primary statistical parity and speed comparison. Keep A–B estimates as an integration cross-check. The EvoSAX population-tensor variant is optional secondary work. Use identical objectives, starting candidate arrays, dtype, budgets, and algorithm settings within each block, plus identical centroids and descriptors for QD. Verify actual initialization and evaluation counts. Independent PRNG paths are expected in B–C.

**Proposed grid pending protocol freeze.** Sphere f1, separable Rastrigin f3, Rosenbrock f8, rotated ellipsoid f10, Schaffers F7 f17 and Gallagher 101 peaks f21. Use BBOB instances 1 and 2, dimensions 10/20/50, P128 and generations 50/150/500. P512 is a separately labeled sensitivity option after costing. Verify the exact function/instance mapping, shifts, and optima before use. The current runner's task names and seed semantics need extension for this grid. See the [COCO BBOB definitions](https://coco-platform.org/testsuites/bbob/overview.html).

**Quality sample and decision.** Plan 100 independent matched blocks per grid cell (candidate seeds 3000–3099), then freeze the actual count from pilot paired variance and simulated power for the intended claim. Use the existing runs for overlapping coordinates and a disjoint new pilot for new cells (candidate seeds 1000–1029, after checking namespace collisions). Target at least 90% power at a true effect of half the margin for the prespecified claim. For initial costing, the conservative normal approximation per cell is n ≈ [(z at 1−α + z at 1−β/2) × paired SD / (margin/2)]². Confirm with the actual TOST or joint decision simulation, accounting for within-block repeated settings and any planned family adjustments. If n exceeds the budget, revise scope before collection.

- Primary quality candidate is log10(max(final objective − verified optimum, ε)), with proposed ε = 1e−8 and a candidate equivalence margin of ±0.05 log10 units (geometric error ratio about 0.891–1.122). These are proposals requiring approval and a numerical-floor check before confirmation. Report floor-hit counts and raw objective contrasts. If this scale is unsuitable, agree on a scientifically meaningful replacement before collecting confirmation data.
- GA endpoint is historical best at the generation budget. QD endpoint is archive-best objective, also reported as maximum archive fitness under the recorded fitness sign convention. Export QD score, coverage, occupied-cell count and the fixed score offset. These are secondary descriptive endpoints unless endpoint-specific margins and claim rules are frozen.
- Fit separate paired OLS models per library using mimic-minus-adapter responses and function, dimension, generation budget and instance factors, with prespecified interactions or saturated setting contrasts where supported. Export equally weighted marginal contrasts and setting-level 95% CIs, accounting for repeated seed blocks if reused across settings. Include a condition/seed-block ANOVA or equivalent joint OLS factor tests as descriptive model summaries. Apply TOST at α=.05 for frozen contrasts and report its 90% CI or prespecified adjusted equivalent separately. A panel-wide claim requires every prespecified setting to pass its equivalence criterion. Specify the family and multiplicity rule for any separate setting-level claims. A pooled near-zero result leaves panel-wide equivalence unresolved. [TOST reference](https://pubmed.ncbi.nlm.nih.gov/3450848/)
- Report synchronized wall-clock, actual evaluations/sec, and geometric mean adapter/mimic speedup with 95% CI by library and setting. Use OLS on paired log timing ratios. Candidate timing design is 12 independent matched timing blocks per cell, five steady repeats after one first prepared call, counterbalanced condition order, and at least three isolated sessions per library distributed over blocks. Cost and freeze counts after pilot. Analyze at block/session level with repeats nested. Separate setup, JIT lowering/compilation, first prepared call, warm-up, steady execution and optional end-to-end wall-clock. Reset from equivalent starting states on repeats. Run actual budgets for timing. Reuse a longer quality trajectory only after checking shorter endpoints agree with standalone runs. [JAX synchronization guidance](https://docs.jax.dev/en/latest/async_dispatch.html)
- Deliver library-specific quality and speed plots across factors, a compact table with separate CI bounds, full contrast and QD tables, model diagnostics and raw quality/timing files.

## Part 2 — Hopper interchangeability

Use genuine Hopper through Brax/MuJoCo MJX, horizon 200, P32, G20, fixed tanh MLP (64,64), shared initial candidate arrays, training seeds 2000–2019 and 20 fresh held-out episodes per selected policy. Hold reward, termination, rollout wrapper, policy representation, training budget, and held-out keys fixed. Swap native GA constant Gaussian mutation, native GA cosine schedule, EvoSAX Open_ES and QDax MAP-Elites. Record distribution-state initialization for Open_ES and the QD archive and descriptor settings separately. Select policies using training data. Existing completed Hopper data are the first source. A fresh run is conditional on missing evidence or an approved protocol change. The existing Gymnax CartPole path is optional separate evidence.

Report per-run held-out mean return, across-seed mean and 95% CI, episode lengths, validity/failure counts, and evaluation counts. Report QD metrics only for QDax. Quantify usability from canonical configs or runnable entry points against the constant GA baseline. Save each unified diff and count added and deleted nonblank, noncomment logical lines using the same formatter and file set. A replacement counts as one deletion plus one addition. Label evaluator/wrapper edits separately from configuration/operator edits. Document any needed adapter-specific components. This is feasibility and usability evidence. Success means finite, interpretable held-out outcomes, auditable component swaps and complete failure accounting. Preserve historical analysis provenance with its original scope. Make no speed or leaderboard claim.

Run random and zero-action sanity controls with the same wrapper/horizon and held-out keys. Audit reward terms and termination. Historical D4RL Hopper reference constants are −20.272305 and 3234.3. Record source, task version, horizon and training regime. Treat them as external context if protocols differ and use the matched local controls for a numerical sanity check. Never rescale external scores by horizon. [D4RL source constants](https://github.com/Farama-Foundation/D4RL/blob/master/d4rl/infos.py) · [Hopper task definition](https://gymnasium.farama.org/v1.3.0/environments/mujoco/hopper/)

## Part 3 — Tensor network + QD + islands

Proposed exact composition for design review is a fixed-shape matrix product state (MPS) policy genome, QDax-style CVT MAP-Elites, and four ring-connected island archives on genuine Brax/MuJoCo MJX Hopper. Use rank 4 with open boundaries and local feature map `[1, tanh(observation_i)]`. Contract one core per observation followed by an action readout, then tanh the action. Initialize once per block and use Gaussian core/readout mutation with a provisional σ=.05 and no crossover. Compare a single archive against the island system with equal total archive capacity (proposed 64 shared global centroid coordinates for reporting, 64 total training slots split into 4×16 for islands), total candidates per generation (32), and 20 generations. Before freeze, specify the global-to-local centroid assignment and routing semantics, including how each island bins any candidate into its local centroid subset. Use H200, 20 matched seeds 2000–2019, common initial candidates, and two migrants per island at G5/10/15 with receiver-side rebinning and deduplication rules recorded. Reuse Phase 2's task definition. Compare maps using the same global centroids and fresh held-out episode keys. Proposed descriptors are the first two valid-step mean action coordinates, scaled to [0,1] with explicit zero-valid-step handling.

**Primary utility measure** is held-out global QD score at equal training evaluation budget, using a fixed reward offset that makes occupied-cell contributions nonnegative on the declared reward scale. Freeze the offset, empty-cell convention and a practically useful score improvement before the full run. Build each final global map by rebinning all final archive members after the same held-out protocol (20 episodes per member) and report held-out evaluation counts. Report coverage, best held-out return, migrant survival, and paired score contrasts with CIs. Capability success means finite valid policies, valid descriptors, auditable migration and reproducible held-out maps. A claim of added utility requires a prespecified practically useful QD-score gain with uncertainty and coverage shown alongside. Mixed or weak results still belong in the record.

The current Phase 3 runner implements NSGA-II/NEAT, so the tensor-network path requires a new harness and a feasibility gate. First verify MPS contraction, mutation, candidate shape, shared inputs, migration counts, and archive insertion on CPU. Then run bounded genuine Hopper validation. If existing interfaces cannot support archive migration without changing core semantics, stop with a minimal reproducer and keep the prior NSGA-II/NEAT study available for a planning decision.

## Order, gates and fallbacks

1. Freeze source/environment, verify direct baselines, capture budgets and dry-run expanded counts. Stop on tracked-source differences, unsupported functions or reproducibility blockers.
2. Run P1 fidelity smoke and pilot. Stop and report the seed-count and runtime forecast before full collection. Stop on unexpected A–B divergence. Save arrays, keys, exact arguments, assertion logs and environment. Inspect objective, initialization, sign, dtype and version mismatches before any retry. No library changes to reconcile results.
3. After each completed part write `results/status_partN.md` and stop before starting the next. P2 reuses eligible retained data and runs missing controls. If Hopper breaks, pin and validate the intended versions in a fresh environment. Any substitute task requires approval and separately labeled evidence. P3 waits for the agreed task contract and composition gate.
4. Publish raw tables, analysis code, plotted/table outputs and their captions with SHA-256 and source lineage. Preserve all attempts and explicitly label exclusions, weak runs and incomplete families. Stop for unexpected anomalies, violated equivalence margins, ambiguous results, or anything affecting the paper claims.
