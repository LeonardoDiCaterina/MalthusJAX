## Part 1 agreed comparison and proposed inference details

**Paper framing:** MalthusJAX uses different PRNG splitting from ordinary upstream runs. We therefore expect different trajectories, and test practical equivalence statistically across many independent seed replicates. Overlapping observed distributions or non-significant condition effects alone do not establish equivalence. Mean-equivalence inference supports a bounded mean-quality claim, not identity of entire distributions; show empirical distributions to expose tails/variance and report failures.

- Stage 1 (a↔b): use the existing EvoSAX and QDax test-suite comparisons summarized below. These use deliberately aligned keys and numerical assertions in selected settings. Cite their actual scope and execution provenance; do not describe them as universal identity or statistical distribution equivalence.
- Stage 2 (b↔c): compare adapter and native implementation on the same task instance, algorithm settings, population, generations, precision and actual evaluation budget. Count initialization and archive evaluation work. Cheap fitness exposes costs, but algorithm work must match before attributing differences to architecture.
- Primary contrasts per coordinate: standard-native–adapter and batched-native–adapter for EvoSAX; native–adapter for QDax. The standard–batched contrast is secondary/descriptive by proposal. No original–native statistical contrast is required; the EvoSAX condition-factor model now has three levels and QDax has two. The evidence chain combines original–adapter numerical fidelity and HLO structural parity as indirect evidence of negligible wrapping overhead, followed by measured adapter–native quality/performance parity. The original–adapter performance argument is structural and indirect, not a direct runtime-equivalence estimate; report this distinction explicitly.
- Independent replicate seeds within each condition; different PRNG streams are expected. Agreed: use a fresh initial population per independent seed block and share it across all compatible contenders within that block; QD conditions also share centroids. Record initialization separately from algorithm keys and verify population hashes. Equal seed labels alone do not justify paired inference. Analyze explicitly paired/block contrasts once this contract is verified. Existing fixed pop_seed=42 across all replicates does not meet fresh-block sampling; resolve runner support before submission, without silently changing production code.
- Retain a condition-factor OLS/ANOVA model, including coordinate/block structure where appropriate; estimate planned mean contrasts with covariance reflecting the design. Interaction/heterogeneity across tasks must remain visible. Non-significance is never the equivalence criterion.
- Proposed primary inference: t-based contrast CIs and TOST. For a single unadjusted test at alpha=.05, equivalence corresponds to a 90% CI lying strictly within the predeclared bounds; also display ordinary 95% estimation CIs. Multiplicity-adjusted decisions/intervals must match the frozen contrast/endpoint family. Bootstrap CIs may be a predeclared sensitivity analysis, with resampling at the independent run/block level, not generations or timing repetitions. Final choice remains open.
- QDax: compare all three requested QD outputs, canonical zero-offset occupied-cell higher-is-better QD score, coverage (0–100), and max fitness. Best fitness and max fitness may be the same signed/oriented quantity: map semantics rather than count it twice. Which metrics are co-primary versus secondary remains open; define separate margins in their own units.
- Speed is separate from quality: synchronized wall-clock time and evaluations/sec for prepared execution, fixed hardware/population/generations and matched output work; compilation/preparation and first-call/warm-up reported separately and excluded from steady-state timings. Record cache policy, order, sessions and all trials. Repeated timing calls are not additional quality seeds. No meaningful slowdown needs its own predeclared relative bound; speedup is estimated rather than required.

### Seed-count proposal (not approved and not a power guarantee)

Propose **100 independent runs per condition per coordinate** as an initial confirmation planning count: 300 trajectories per EvoSAX coordinate (adapter + standard native wrappers + batched native wrappers), and 200 per QDax coordinate (adapter + native). Existing original–adapter tests are not counted as independent statistical replicates. Use a separate **30-run-per-condition planning pilot** at the exact workload to estimate contrast variability and cost; retain pilot outcomes visibly but exclude them from confirmation. Freeze final n before confirmation, using an upper variance estimate. The earlier paired two-endpoint power draft is not automatically valid for this revised adapter–native/multi-endpoint family.

For a blocked contrast with difference SD s_d, ordinary 95% t-CI half-width is approximately `t_(.975,n-1) * s_d / sqrt(n)`. At n=100 this is about `.198*s_d`: below margin Delta only if `s_d < 5.04*Delta`. For independent equal-size conditions with common SD s, half-width is approximately `t_(.975,2n-2) * s * sqrt(2/n)`; at n=100 it is about `.279*s`. These are precision illustrations, not observed variances or assurances of equivalence.

Proposed precision target: half-width <= Delta/2 for each primary contrast/endpoint, using simultaneous critical values once the family is fixed. Approximate planning equations are `n >= (c*s_d/(Delta/2))^2` for blocked contrasts, or `n >= 2*(c*s/(Delta/2))^2` per condition for equal-variance independent contrasts; refine with t quantiles/unequal variances. Centering matters: a narrow CI outside the margin still fails equivalence. Also check modeled TOST power at true differences zero and Delta/2; a precision target alone does not guarantee power. Proposed cap remains 200 per condition, subject to resources; if insufficient, revisit resources or report inconclusive results, never widen margins to pass. Final pilot size, n, power target and cap await agreement.

## Part 2: quantified feasibility demonstration (not a benchmark)

Part 2 is a feasibility demonstration, not a comparative performance benchmark or leaderboard. Success means an end-to-end experiment with valid, sensible, quantified outputs; it does not require one algorithm to outperform another or achieve equivalent returns. Conclusions apply to the demonstrated combinations, not arbitrary libraries/tasks.

**Required quantification (protocol details still open):**

- Task behavior: per-seed final episodic return and learning curves against actual evaluations, with descriptive central tendency and spread/intervals across independent seeds. Define reward, horizon, termination and return aggregation. Evaluate final policies on separately specified evaluation episodes/seeds. A random or untrained policy reference can contextualize sensible behavior; it is not an algorithm leaderboard or a mandatory superiority test.
- QD combinations: report coverage, best return and canonical QD score with the exact descriptors/archive and metric definitions, where supported. No cross-method archive-quality claim follows from incompatible descriptor contracts.

Expose any adapters/glue or incompatible requirements rather than counting only the final invocation.

Descriptive uncertainty helps show reliability; no pairwise significance testing, equivalence testing or winner selection is required for Part 2.
