# P9 — Run validation and immutable snapshots

Required best-fitness summaries must be finite; a known requested horizon must match the reported completed horizon. Failures keep a reason and do not become successful runs. Legacy records containing a nonfinite best objective serialize as invalid and preserve the unavailable-value reason. Optional unavailable numbers become JSON null, not NaN/Infinity. Unsupported timeouts raise before execution; no background operation is claimed cancelled.

Runner captures a configuration snapshot/hash, declaring unknown or partially serializable runtime configuration explicitly. Composer supplies its structured configuration. Source fingerprints cover package Python contents, alongside revision/dirty/diff identity, package versions, hardware/backend, precision, XLA flags, seeds/order and timing policy. Each artifact export creates a uniquely named immutable manifest containing complete raw experiment results and output hashes. Legacy convenience summary filenames may be reused; earlier raw results remain in their immutable snapshots and hash differences expose replacement. Default Composer runs use unique run directories to avoid mixing outputs.

`requirements/analysis-cpu-candidate.txt` pins the relevant scientific stack used by the local CPU checks only. It is explicitly not an approved GPU/publication lock or a blind freeze of unrelated system packages. Publication environment approval and hardware replication remain visible prerequisites; the custom cluster JAX build is not silently substituted with a PyPI approximation.

The manifest test preserves an earlier snapshot byte-for-byte while another run is exported. Configuration with runtime-only objects remains explicitly partial, not promised to be reconstructible automatically. Missing input data and failed/invalid runs remain visible rather than selectively dropped.
