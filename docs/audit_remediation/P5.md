# P5 — Crowding distances and crossover batch contracts

Findings A05 and A13 are repaired on the remediation branch. Scope is the pure-JAX crowding primitive and the two batched `BaseCrossover` paths, with independent mathematical and integration regressions. No GPU experiment or manuscript regeneration was launched.

## Front-local crowding

The audit input `[[0,10], [1,6], [4,3], [10,0], [1000,20]]` with ranks `[0,0,0,0,1]` previously returned interior distances approximately **0.354 and 0.309**, reversing their ordering. The correct front-local distances are **1.1 and 1.5**. Both normalization endpoints now come from the individual's own front for each objective. Forward/backward scans locate front boundaries after deterministic rank/objective/index sorting, avoiding an additional dense N-by-N crowding mask. Contributions remain summed across objectives, preserving the existing sum convention.

An independent NumPy reference loops explicitly over fronts and objectives. Tests compare eager/JIT reductions against it for multiple/gapped fronts, duplicates, singleton/pair/empty fronts, constant objectives, randomly generated fronts, tiny ranges, and finite values whose range subtraction overflows float32. The latter uses a scaled normalization fallback; ordinary nonzero ranges do not receive an arbitrary epsilon floor. Actual `MOPopulation.from_evaluated(...).truncate(3)` tests retain the same survivor identities before and after appending a dominated front, in eager and compiled execution.

Degenerate/invalid conventions are explicit:

- An objective constant within a front contributes zero, including its arbitrary sorted endpoints. Fronts of at most two members receive infinity; larger all-identical fronts receive zero distances.
- Ties are resolved deterministically by original index. Permutation invariance for distinguishable points does not imply a unique choice among identical tied individuals.
- Empty `(0,M)` inputs return an empty vector. Invalid shape, zero objective count, noninteger ranks, or non-real fitness dtype raise at trace time.
- Nonfinite fitness or negative runtime ranks produce all-NaN unavailable distances in eager/JIT execution, without host callbacks or fabricated boundary rewards. This is a primitive-level invalidity signal; P9 still owns complete run-status validation.

The existing test that assumed population-wide normalization now asserts the front-local reference. This changes MO diversity selection and can change trajectories; historical MO evidence, if used in the paper, requires P10 review. Dominance and front-peeling logic were not changed.

## Crossover batch and key validation

The array fast path previously referenced an undefined `flat_values` when the default `input_length=-1` was used. Pair counts now come from the actual two parent arrays. The population path uses the same validation over all registered gene-PyTree leaves, instead of relying on a `.values` array or population length fallback.

Both paths reject mismatching parent structures/shapes/leading batch counts, invalid configured lengths, and wrong PRNG budgets before reshaping/vmap. Configured `input_length >= 0` must equal the actual pair count; `-1` means infer. In particular, configured zero now explicitly means an empty batch. Exactly `pairs * offspring * atomic_keys` keys are consumed; no extra split, key reuse, or truncation is introduced. Typed keys are recognized by the actual PRNG dtype, not the existing broad helper that treats any non-legacy array as a typed key. Legacy keys retain the `uint32[...,2]` layout contract. Both flat split-key batches and grouped key layouts are accepted.

The array fast path still explicitly rejects multiple offspring. The population path supports them and preserves pair-major ordering, including structured gene PyTrees and deterministic zero-key operators. `cross_single_pair` and mutation behavior were not changed. Tests cover typed/legacy keys, inferred/configured length, eager/JIT execution, exact uniform-crossover parity, Blend parity within float32 rounding tolerance, malformed parent widths/counts/trees, excess/missing keys, numeric impostor key arrays, empty batches, and zero-key/multiple-offspring cases.
