# Agent prompt for the MalthusJAX paper pipeline

## Mission

Implement and execute the approved research pipeline. The paper evaluates EvoSAX and QDax integration fidelity, statistical parity and execution cost, demonstrates quantified algorithm interchangeability on a fixed Hopper task, and documents an approved composition showcase. Produce retained per-run evidence, reproducible analysis, paper-ready figures and tables, and a manifest connecting results to configurations and source. The proposed new showcase is MPS policy genomes with QDax-style MAP-Elites and islands on Hopper. The existing Part 3 uses NSGA-II/NEAT and remains valid historical evidence. Ask the paper owner to resolve their relationship before implementing a claim change.

## Execution tasks

Use an activated pinned Python environment and run `export PYTHONPATH="$PWD/src"`. Shell examples below use `RUN=results/paper-confirmatory-v1` and `REV="$(git rev-parse HEAD)"`. Use fresh paths on retries and retain the prior attempt. Proposed interfaces become runnable after implementation. For new collection entry points implement the plan's CLI and verify dry expansion. For the new Slurm launcher implement `--part N --stage pilot|full --config PATH --expect-revision REV --output NEW_DIR`, using isolated H100 allocations and an approved cap. For both new analysis and rendering scripts implement `--part N --input DIR --output DIR`. Validate scripts, configs and output schemas with small deterministic fixtures before collection.

1. **Freeze and preflight.** Inputs are both decision notes, the implementation plan, environment snapshot and prior ledgers. Run `git status --short`, `git rev-parse HEAD`, and `mkdir -p "$RUN" logs/paper-confirmatory-v1`. Inside the intended allocation run `python docs/handoff/capture_cluster_environment.py --probe-jax --output "$RUN/environment_capture.json"`. Save `$RUN/protocol_freeze.json` with final script/config hashes, exact versions and build sources, estimands, seeds, margins, device, time caps, and open issues. **Pass** when observed imports/backend match the lock, resources are available, and scientific choices needed for the current stage are explicitly fixed. Full run preflight fails on unresolved gates. Report missing paths or approvals.
2. **P1 fidelity and local smoke.** Inputs are pinned direct originals, adapters and native mimics, H1 configs, existing tests. Run `python -m pytest tests/composer/test_composable_evosax_adapter_parity.py tests/composer/test_adapter_hlo.py tests/composer/test_qdax_oracle_parity.py tests/operators/selection/test_evosax_selection_parity.py tests/operators/mutation/test_evosax_mutation_parity.py tests/operators/crossover/test_evosax_crossover_parity.py` and retain test logs in `$RUN/part1/fidelity/`. Run `python scripts/run_publication_part1_confirmatory.py --config configs/publication/part1_confirmatory.json --stage preflight --output "$RUN/part1/preflight"` and repeat with `--stage smoke --output "$RUN/part1/smoke"`. **Pass** when all six direct/adapter/native paths consume matched inputs, recorded evaluation counts and signs agree, supported regression assertions pass, and pilot workload counts resolve.
3. **P1 pilot and confirmation.** Use retained historical data and a disjoint pilot. From the cluster checkout submit `sbatch --output=logs/paper-confirmatory-v1/%x-%j.out --error=logs/paper-confirmatory-v1/%x-%j.err scripts/submit_publication_confirmatory.sh --part 1 --stage pilot --config configs/publication/part1_confirmatory.json --expect-revision "$REV" --output "$RUN/part1/pilot"`. Retain raw pilot data, power calculation and wall-time forecast. **Pause** for margin, n, timing repetition/session and budget approval. With frozen approval, use the same command with `--stage full` and `$RUN/part1/full`. **Pass** for collection when raw quality/timing rows cover all expected pairs or explicitly identify missing runs and their reasons, actual evaluation counts match, timings are synchronized and phase-separated, and provenance is complete. Run analysis and rendering using the common commands below. Report at `results/status_part1.md` and stop. An inconclusive or violated equivalence margin is an analysis result to report and review.
4. **P2 Hopper feasibility and usability.** Use the existing retained ledger first. Run `python scripts/run_publication_phase2.py --smoke --environment hopper --seeds 9000 --output "$RUN/part2/smoke"` to validate the target environment if the stack or runner changes. Implement the audit interface `python scripts/audit_publication_part2.py --config configs/publication/part2_feasibility.json --ledger results/paper-study-v2/phase2/campaign.json --output "$RUN/part2/audit"`. Use config to declare canonical swap entry points and reference/held-out keys. Run matched controls on an approved allocation via the P2 audit script's `--controls --output "$RUN/part2/controls"` mode with the same config and ledger. If an approved equivalent full rerun is needed, invoke on the allocated worker `python scripts/run_publication_phase2.py --environment hopper --study-mode feasibility --seeds $(seq 2000 2019) --population 32 --generations 20 --horizon 200 --eval-episodes 20 --conditions native_ga native_ga_cosine evosax_open_es qdax_map_elites --output "$RUN/part2/full"`. Expected outputs are run/episode CSV or Parquet, matched controls, reference protocol comparison and unified swap diffs with line counts. **Pass** when genuine Hopper is verified, held-out keys differ from training keys, accounting covers all expected runs, returns are interpretable and swaps leave the task fixed. If retained data came from historical ranking mode, preserve that provenance. Analyze and render. Report at `results/status_part2.md` and stop.
5. **P3 tensor network composition.** Inputs are the approved scope, frozen Hopper contract from P2, and MPS/QD/island config. Run `python scripts/run_publication_part3_tensor_qd.py --config configs/publication/part3_tensor_qd.json --stage smoke --output "$RUN/part3/smoke"`. **Pass** when fixed-shape contraction produces bounded actions, route checks prove correct migration and budgets, and the single/archive-island conditions produce finite maps. Run a bounded H100 pilot and approved full job using the P1 Slurm command template with `--part 3`, the P3 config, and `$RUN/part3/pilot` or `$RUN/part3/full`. **Pause** after pilot to freeze scoring offset, practical gain threshold and cost. Expected outputs include per-seed summaries, candidate/episode data, archive occupancies and migrant records. **Pass** for capability when held-out maps are reconstructible with validated descriptors, shared inputs, and complete accounting. Report utility using its frozen criterion. Analyze and render. Report at `results/status_part3.md` and stop.
6. **Analysis and final assembly.** For each part, before its status checkpoint, run `python scripts/analyze_publication_confirmatory.py --part "$N" --input "$RUN/part$N" --output "$RUN/part$N/analysis"` and `python scripts/render_publication_confirmatory.py --part "$N" --input "$RUN/part$N/analysis" --output "$RUN/part$N"` (renderer writes fresh `figures/` and `tables/`). After the final checkpoint is reviewed, compile `$RUN/output_manifest.json` and `$RUN/OUTPUTS.md` from all parts. **Pass** when tables reconcile to raw retained rows, labels and CI bounds are correct, figures regenerate from recorded inputs, and all paths/hashes resolve. Include analysis scripts, machine-readable summaries, tables (CSV and TeX), figures (PDF and a preview format), captions, config/command paths, logs and exclusion/failure inventory.

## Rules and checkpoint contents

- Do not modify library core or adapter code to make results look better. On a bug, stop with the minimal reproducer and exact source identities.
- Set seeds explicitly. For every run record the seed, git commit, script/config hashes, library versions, environment and condition. Keep the same initial candidates within each matched block and record actual array hashes. Keep JIT and warm-up separate from steady-state timings.
- Save raw per-run CSV or Parquet. Preserve per-episode and timing-repeat records where applicable. Keep failed, weak and partial runs visible with statuses and reasons. Keep old and new campaigns distinct.
- Make no speed claims in Part 2. Scope any quality, equivalence, speed or composability claim to the frozen task and endpoints.
- After each part write `results/status_partN.md` with commands/jobs, what ran and failed, key numbers with uncertainty, pointers to evidence and open issues. Stop and report before proceeding. Preserve any previous status as a dated copy if the path already exists.
- Stop and ask the owner about ambiguous results, an equivalence margin violation, unexpected original–adapter divergence, an unsupported environment, or any change affecting a paper claim. Report evidence and practical options. Keep failed attempts and frozen settings intact.
